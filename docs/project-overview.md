# Project Overview

## Product

Copy Stack is a local-first macOS clipboard manager built with Tauri, React,
TypeScript, Rust, and SQLite. It captures eligible clipboard changes, stores a
bounded local history, restores previous items, and exposes a small recent-item
view through the menu bar.

There is no account, cloud sync, remote API, or telemetry in the current
codebase.

## Current Capabilities

- Capture clipboard events through the published
  `copy_event_listener = "0.1.2"` crate.
- Apply an event-wide NSPasteboard policy before content inspection so
  transient, autogenerated, concealed, and supported password-manager content
  never reaches persistence, previews, the menu bar, or the optional mirror.
- Persist accepted payloads as bounded binary blobs with source metadata,
  remote-device provenance, compact summary metadata, and accounted byte size.
- Render history in stable 50-item cursor pages and fetch rich detail only when
  an eligible card is expanded.
- Restore an item from History or the menu bar with canonical source and remote
  protocol markers.
- Delete one item or clear all history.
- Enforce both an item-count limit and an accounted history-byte limit.
- Configure compact text-only mode, restore ordering, language, and menu bar
  visibility.
- Keep one owning process. A later launch activates the existing main window
  without creating another database, tray, or clipboard listener.
- Configure the operating system login item. Login launches stay hidden while
  clipboard capture and the menu bar remain active.
- Optionally mirror accepted history to a private JSONL snapshot through a
  coalescing background worker.

## Primary User Workflows

### Browse History

The main window loads one page of bounded summaries ordered by persisted
recency. More pages load on request. Rich HTML/image/video detail is built
outside the database lock and fetched only after expansion. Background refresh
preserves the current scroll anchor and expanded-card state.

### Restore Previous Content

The backend reads a restore seed while holding the database lock, decodes it
after releasing the lock, replaces protocol metadata with exactly one source
marker and the stored remote marker when applicable, then writes it to the
system clipboard.

When restore-to-top is disabled, a short suppression window prevents the app's
own clipboard write from being captured as a new event. When it is enabled, the
row receives a new persisted ordering timestamp and History and the menu bar are
refreshed.

### Keep History Bounded

Settings exposes the item-count limit and current accounted storage usage.
Lowering the item limit asks for confirmation. The backend also enforces the
persisted `max_history_bytes` setting, which defaults to 256 MiB. Cleanup removes
the oldest rows until both limits are satisfied.

### Menu Bar Access

The menu bar reads a summary-only query with a hard `LIMIT 20`. It never decodes
event blobs or reads rich local media while rebuilding the menu.

## Non-Goals

- Cross-device history synchronization.
- Search, tags, categories, or filtering.
- User-facing import/export. The optional JSONL mirror is a development
  startup feature and may contain sensitive content.
- Global keyboard shortcuts.
- Rich previews for every clipboard format.
- Runtime support outside the current macOS-focused implementation and release
  matrix.

## Data Privacy And Failure Model

History lives at `$HOME/.copy_stack/copy_stack.db`. The directory is created or
tightened to `0700`; the database, SQLite sidecars, JSONL output, and JSONL
temporary files are created or tightened to `0600`. Unsafe symlink,
non-regular, wrong-owner, multiply linked, or insecure targets are rejected
instead of falling back to a public path.

Command failures cross IPC as stable `{code, operation, retryable}` values.
Diagnostics are bounded and contain only version, platform, architecture,
timestamp, and those enumerated fields. They do not contain clipboard bodies,
source identifiers, content hashes, HTML, or local paths.

## Verification Status

Automated tests and structural performance budgets do not replace native
behavior checks. Before a release, complete and record the Apple Silicon and
Intel scenarios in `docs/security-release-checklist.md`, including protocol
markers, restore metadata, private permissions, single-instance activation,
launch at login, paging, and mirror fault behavior.
